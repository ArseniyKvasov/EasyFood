# BiteBalance — лендинг

Статичный прототип посадочной страницы: один экран-витрина продукта (дневник питания
с распознаванием еды по фото, сканером штрихкодов и календарём баланса).

Сборка не нужна — открывается двойным кликом по `index.html`.

    open index.html
    # или локальный сервер (нужен для камеры: getUserMedia требует https/localhost)
    python3 -m http.server 8765

## Дизайн-токены

    --cream   #FAF6EF   фон
    --paper   #FFFDF8   карточки
    --ink     #1B211D   текст
    --green   #2F6B4F   основной акцент
    --lime    #C9F26B   подсветка, CTA
    --coral   #E8735A   «перебор» в календаре

системный стек — вёрстка не поедет.

## Анимация

Темп намеренно медленный: длинные выдохи вместо пружинок.

| Что | Длительность |
|-----|--------------|
| Появление блоков при скролле | 1,4 с, `cubic-bezier(.22,1,.36,1)` |
| Выезд строк заголовка | 1,7 с со стаггером 0,14 с |
| Заливка кольца калорий | 2,9 с, счётчик — 2,8 с |
| Параллакс телефона за курсором | lerp 0,028 за кадр |
| Дрейф фоновых пятен | 38–46 с |
| Подсветка финального блока | 18 с |
| Сканирующий луч штрихкода | 4,6 с |
| Покачивание плавающей карточки | 9 с |

Всё это отключается через `@media (prefers-reduced-motion: reduce)` — там же
заданы статичные конечные состояния, чтобы страница не оставалась пустой.

Чтобы ускорить или замедлить — правьте `transition`/`animation` в соответствующих
блоках `styles.css`. Быстрый способ «сделать бодрее» — уменьшить `--d` задержки
в разметке и длительности в правилах `.reveal`, `.h1 .line>span`, `.ring__fill`.

## Онбординг

Прототип лежит отдельно: `/onboarding/` (при сервере на 8765 — http://127.0.0.1:8765/onboarding/).

Сценарий: шторка поверх пустого дневника → цель (минус 15% / без поправок / плюс 10%)
→ пол, возраст, рост, вес, активность → проверка нормы с ручной правкой → первый приём пищи
через фото, штрихкод или поиск. Пропустить шаги нельзя.

После «Готово» внизу главной появляется баннер «Добавить приложение на главный экран»,
а поверх открывается инструкция из существующего виджета приложения: вкладки iPhone/Android,
браузеры и пошаговые подсказки. Закрыть - крестик или «Понятно», повторно открыть - тап
по баннеру. Кнопка «Заново» сбрасывает весь сценарий.

Норма считается по формуле Миффлина-Сан Жеора с нижней границей 1 200 ккал (женщины)
и 1 500 (мужчины). Белок 1,7 г/кг, жир 0,9 г/кг, углеводы остатком.

## Тарифы и оплата

Модель: Free и Plus, два пейволла на разные ценности.

| | Free | Plus |
|---|---|---|
| Дневник, поиск, штрихкод | без лимита | без лимита |
| Фото | 30 в месяц | без лимита, до 50 в день |
| История | 60 дней | пока есть аккаунт |
| Тренды и экспорт | — | есть |
| Цена | 0 ₽ | 1 990 ₽ в год или 299 ₽ в месяц |

В прототипе квота уменьшена до 3 фото, чтобы пейволл можно было увидеть сразу:
три снимка через «+» → четвёртый открывает шторку Plus. Оплата имитируется
(кнопка «Оформляем подписку…», через 1,5 с успех), реального запроса к эквайрингу нет.
Пробного периода в интерфейсе нет: кнопка сразу оформляет подписку на выбранный срок.
В оферте осталась формулировка «может быть предоставлен», чтобы период можно было включить позже.

Логика в коде: `S.photoQuota`, `S.photosUsed`, `S.plan`, `openPaywall(mode)`,
`startPayment()`. Режимы пейволла: `quota` (кончились фото), `feature` (экспорт),
`plan` (из настроек).

## Документы

Раздел `/legal/` — три документа и страница-оглавление:

- `privacy.html` — политика обработки персональных данных по 152-ФЗ;
- `consent.html` — согласие на обработку, включая данные о здоровье, рассылки и cookie;
- `offer.html` — публичная оферта: тарифы, оплата через Т-Банк, рекуррентные списания,
  пробный период, возвраты.

Всё это шаблоны под проверку юристом. Заполнить перед публикацией:
ОГРНИП, адрес, телефон, домен и перечень стран для трансграничной передачи.

## Напоминания

В прототипе: после первой записи появляется вопрос «Напомнить завтра про обед?» с временем,
подставленным по текущему приёму пищи. Дальше раздел «Напоминания» в настройках: три
переключателя с временем, добавление своего (до трёх на Free), сохранение.

Логика в коде: `S.reminders`, `renderReminders()`, `openAsk()`, `askSuggestion()`.
Правило «умной тишины» (не напоминать, если приём пищи уже записан) описано
в `docs/notifications.md`, в прототипе оно не реализовано — там один день.

## Вход и аналитика

Все кнопки входа ведут на `loginUrl` из `config.js` — по умолчанию `/app/`, там живёт
приложение с авторизацией через Яндекс ID. Лендинг сам аккаунтов не создаёт.

    window.BB_CONFIG = {
      loginUrl: '/app/',
      metrikaId: 114649881,
      clarityId: 'zio99z39fu',
      debug: false
    };

Аналитика — Яндекс.Метрика и Microsoft Clarity. Оба счётчика подключаются только после
согласия в cookie-баннере: при отказе не грузится ничего, кроме технических cookie.
События уходят через `bbTrack('name', { ... })` — в Метрику как цели, в Clarity как
события и в `dataLayer`. UTM фиксируются при первом заходе.

## Калькулятор

Страница `/calculator/` — самостоятельный вход в продукт: считает норму по Миффлина-Сан
Жеору, БЖУ, показывает результат и ведёт в дневник. В `sitemap.xml` отмечена отдельным адресом,
в `robots.txt` разрешена.

## Установка на экран

`manifest.webmanifest` плюс `sw.js` дают установку и офлайн-кэш статики. Иконки лежат в
`assets/icon-180.png`, `icon-192.png`, `icon-512.png`. Service worker регистрируется только
на лендинге и не кэширует обращения к API.

## Деплой

Сборки нет, всё статика. Три способа запустить:

    npm run serve                 # локально на 8765
    docker build -t bitebalance . # образ nginx со статикой
    docker run -p 8080:80 bitebalance

Конфиг nginx лежит в `deploy/nginx.conf`: gzip, кэш на статику, заголовки безопасности
и CSP, запрет отдавать `scripts/`, `docs/` и `preview/`, страница 404.

Перед публикацией замените `bitebalance.ru` в `sitemap.xml` и `robots.txt` и домен
в юридических документах.

## Проверки

    npm run check

Скрипт `scripts/check.mjs` обходит все страницы и проверяет: битые внутренние ссылки
и якоря, повторяющиеся id, `alt` у картинок, наличие title и description, обязательные
файлы вроде `robots.txt` и `404.html`.

## Что заменить перед публикацией

- **Отзывы** — цитаты демонстрационные, фотографии взяты из присланного набора
  (это модели, а не клиенты). Перед публикацией замените на реальные отзывы
  и получите у людей согласие на использование фото.
- **Цифры** — «60 дней истории» и «17 дней подряд» взяты из описания продукта;
  «0 рекламы» и «бесплатно» стоит подтвердить перед публикацией.
- **Ссылки** — все CTA ведут на `#start` (внутренний якорь). Замените на
  `https://<домен>/login` или на Яндекс-авторизацию.
- **Демо-поиск** — база из 10 продуктов лежит в `DB` в `script.js`; это витрина
  механики, а не реальный каталог.
- **Камера** — тянет ZXing с unpkg. Для продакшена лучше положить библиотеку
  локально в `vendor/`, чтобы сканер не зависел от сети. Декодирование работает
  только по HTTPS или на localhost.
- **og:image** — добавьте превью 1200×630 для соцсетей.

## Поведение без JS

Есть `<noscript>`-фолбэк: контент виден, кольцо и календарь дорисованы,
интерактив (поиск, камера, аккордеон) просто не работает.
